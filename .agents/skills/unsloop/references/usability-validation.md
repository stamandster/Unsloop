# Reader, Usability, and Accessibility Validation

Read this file when a user asks whether readers can understand, find, or perform something, or when procedures, policies, plans, forms, or technical documentation require human-use validation.

## Define the validation contract

Identify representative audience, prior knowledge, language, assistive needs, tasks, artifact version, environment, success criteria, error tolerance, safety constraints, facilitator role, data collection, consent, and privacy. Distinguish real participant testing from expert review, automated checks, desk checks, and simulated reader hypotheses.

## Validate proportionately

- **Comprehension:** ask readers to explain meaning, decisions, obligations, risks, and next action without leading prompts.
- **Findability:** test whether readers locate the right entry point, prerequisite, definition, exception, or recovery path.
- **Task performance:** observe completion, errors, hesitation, backtracking, time, recovery, and escalation using the intended environment.
- **Accessibility:** check structure, headings, labels, link purpose, reading order, alternatives for non-text content, keyboard or assistive operation, contrast or visual dependence, language clarity, and required standard with appropriate tools or reviewers.
- **Plain language and localization:** test terminology, sentence load, assumed knowledge, cultural or jurisdictional fit, and translation-specific ambiguity with the intended audience.
- **Delivery and presentation:** test actual duration, pacing, pauses, audience orientation, media handling, transitions, audibility or playback, interaction, and closing comprehension in the intended setting. A model estimate or word-count calculation is not an observed rehearsal.

Do not manufacture participants or observations. Label model-only output **Simulated hypothesis**, automated output **Automated check**, expert inspection **Expert review**, and actual sessions **Observed test**.

## Process findings

For each finding, record task or passage, method, participant or reviewer category, observation, consequence, severity, confidence, proposed change, owner, disposition, retest status, and artifact version. Protect participant privacy and avoid generalizing beyond the tested group.

## Return readiness

State validation type, audience and environment, coverage, observed results, unresolved barriers, changes applied, retest status, and qualified-review boundary. Passing automated checks or a model review does not establish accessibility conformance or human usability.
